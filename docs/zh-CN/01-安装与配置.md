# 1. 安装与配置

以下所有操作都在 **Linux 宿主机**上执行，只有游戏本体由 Proton 运行。

## 前置条件

- **Steam + Limbus Company**，用 Steam Play / Proton 安装，并且**先不带加载器启动过至少一次**。
  这一步才会生成加载器所需的前缀（prefix）与 Addressables 缓存。如果 `compatdata/1973530/`
  还不存在，后面的步骤都不会成功。
  （实测兼容层为 **GE-Proton 11.5**；官方 Proton 应当表现一致，因为这里不依赖 Proton 的版本——
  加载器只是在磁盘上读前缀。）
- 宿主机上有 **Python 3.10+**（实测 3.12）。
- 本仓库的加载器源码（`loader/`）。

## 第 1 步 —— 安装依赖

```bash
cd loader
python3 -m venv venv-linux
venv-linux/bin/pip install -r requirements-linux.txt
```

**不要**复用 Windows 的 venv，也不要装进 Proton 前缀。加载器就是一个普通的 Linux 进程，
它把游戏作为子进程启动。

## 第 2 步 —— 找到你的路径

三个目录最关键。若 Steam 库不是默认位置，自行替换：

```bash
STEAM="$HOME/.local/share/Steam"                       # 原生 Steam
# STEAM="$HOME/.steam/steam"                           # 原生 Steam 的另一常见路径
# STEAM="$HOME/.var/app/com.valvesoftware.Steam/data/Steam"   # Flatpak 版 Steam

GAME="$STEAM/steamapps/common/Limbus Company"
PREFIX="$STEAM/steamapps/compatdata/1973530/pfx"

# 游戏眼中的 AppData/Roaming（位于前缀内部）：
find "$PREFIX/drive_c/users" -maxdepth 3 -type d -name Roaming
```

最后一条命令通常会输出

```
.../compatdata/1973530/pfx/drive_c/users/steamuser/AppData/Roaming
```

mod 目录就是它下面的 `LimbusCompanyMods`（首次启动时自动创建）。

| 用途 | 位置 |
| --- | --- |
| 待安装的 mod | `<AppData>/Roaming/LimbusCompanyMods/` |
| 加载器日志 | `<AppData>/Roaming/LimbusCompanyMods/log.txt` |
| 被加载器打补丁的 Addressables 缓存 | `<AppData>/LocalLow/Unity/ProjectMoon_LimbusCompany/*/*/` |
| 游戏日志（崩溃、Addressables 报错） | `<AppData>/LocalLow/ProjectMoon/LimbusCompany/Player.log` |
| 音频 bank | `$GAME/LimbusCompany_Data/StreamingAssets/Assets/Sound/FMODBuilds/Desktop/` |

若你的 Steam 库没被自动发现：加载器还会读取 `libraryfolders.vdf` 里的每一条路径；也可以直接跳过探测：

```bash
export LIMBUS_GAME_DIR="/path/to/steamapps/common/Limbus Company"
```

AppData 也有对应覆盖项（`APPDATA=...`），用于把加载器指向别的前缀。

## 第 3 步 —— 配置 Steam 启动选项

右键 **Limbus Company** → **属性** → **通用** → **启动选项**，填入：

```
"/绝对路径/loader/run-linux.sh" %command%
```

两点必须注意：

- **脚本路径要加引号。** 干净检出时路径里通常没有空格，但整串值是一条类 shell 命令行，
  Steam 不会替你加引号。
- **`%command%` 不能删。** Steam 会把它展开成真正的启动命令（含 Proton 包装层）。
  `run-linux.sh` 用 `exec` 把加载器和这些参数一起启动，`main.py` 再用
  `subprocess.call(sys.argv[1:])` 把游戏跑起来。加载器由此成为游戏进程的**父进程**——
  原因见 [文档 2](02-工作原理与移植改造.md#2-不靠-tasklist-也能还原资产)。

## 第 4 步 —— 首次启动

从 Steam 启动游戏。首次运行时加载器会：

1. 还原上一次可能残留的补丁；
2. 把 mod 目录里每个 `*.zip` 转成 `*.carra2`（**并删除原 zip**）；
3. 把 mod 对象解压到临时目录；
4. 把每个目标 `<bundle>/__data` 备份成 `__original`，再写入打过补丁的 `__data`；
5. 把 mod 目录里的 `*.bank` 覆盖到游戏音频目录（保留 `.bank.bak` 备份）；
6. 启动游戏并等待其退出，然后还原全部改动。

观察运行情况：

```bash
tail -f "$PREFIX/drive_c/users/steamuser/AppData/Roaming/LimbusCompanyMods/log.txt"
```

你要找的是 `* Patching complete <hash> (<size>) -> <hash> (<size>)` 这类行。想确认游戏确实是被
加载器拉起来的，看日志是否以 `Starting game` 结尾，**同时**游戏窗口出现。

> **一次性清缓存。** 如果你是第一次用任何 mod 加载器，上游那条建议依然成立：清一次
> Addressables 缓存，把以前实验残留的补丁状态清掉。见下方「恢复到干净状态」。

## 第 5 步 —— 安装 mod

把文件丢进 `LimbusCompanyMods/` 然后重启游戏。支持的输入：

| 文件 | 含义 |
| --- | --- |
| `*.zip` | Lunartique 格式。启动时转成 `.carra2`，**原 zip 会被删除** |
| `*.carra` | 较旧的已压缩格式 |
| `*.carra2` | 当前格式；一般最后都会落到这个 |
| `*.bank` | FMOD 音频 bank（语音／音效替换） |

每份下载的 `.zip` 都请自己留一份——转换是不可逆的。
除非你清楚覆盖顺序，否则不要放两个重写**同一个 bundle** 的 mod；见
[文档 4](04-模组格式与取证.md#mod-重叠)。

## 恢复到干净状态

这套加载器的设计是可逆的：

- **卸载某个 mod**：把它的文件移出 `LimbusCompanyMods/` 再重启。下次启动时，加载器会把加载器
  打过补丁的每个 bundle 用 `__original` 还原回 `__data`。
- **强制完全还原**：先退出游戏，然后对每个缓存 bundle 目录，用 `__original` 覆盖 `__data`：

  ```bash
  for d in "$PREFIX"/drive_c/users/*/AppData/LocalLow/Unity/ProjectMoon_LimbusCompany/*/*/; do
      [ -f "$d/__original" ] && mv -f "$d/__original" "$d/__data"
  done
  ```

  （这正是 `patch.cleanup_assets()` 做的事；当崩溃中断了自动清理时，手动执行它就是恢复手段——
  见[文档 3](03-疑难排查.md#缓存残留打补丁后的-__data-没还原)。）

- **音频 bank**：加载器会在每个被替换的 bank 旁留下 `<bank>.bank.bak`。删掉打过补丁的 `.bank`、
  把 `.bak` 改回原名即可；或者直接把该 `.bank` 移出 mod 目录再重启。

## 不启动游戏也能验证环境

在信任启动选项之前，可以手动跑一遍发现逻辑：

```bash
cd loader
venv-linux/bin/python -c "
from platform_paths import steam_roots, library_roots, find_game_dir, find_prefix, get_appdata
print('steam roots  :', *steam_roots(), sep='\n  ')
print('libraries    :', *library_roots(), sep='\n  ')
print('game dir     :', find_game_dir())
print('prefix       :', find_prefix())
print('appdata      :', get_appdata())
"
```

任何一条抛 `FileNotFoundError`，其报错信息都会明确告诉你是缺什么（游戏没启动过、前缀不存在、
Steam 不在我们查找的位置）。
